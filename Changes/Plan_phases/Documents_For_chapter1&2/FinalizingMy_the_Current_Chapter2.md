# System Architecture

The SafeBooks system follows a web-based client-server architecture, where bookkeepers interact with the system through a web browser, while data processing, storage, and system functionalities are managed on a centralized server. This architecture enables centralized management of client financial records, secure data handling, and efficient access to system features such as financial tracking, compliance monitoring, analytics, forecasting, and reporting.  

The system consists of several key components. The primary users are bookkeepers who access the system to manage client profiles, encode financial records, monitor compliance-related information, and generate reports. The user interface serves as the front-end component, providing forms, dashboards, analytics views, and report views that allow users to interact with the system. The application server handles the core system processes, including data validation, record management, TIN-based search functionality, financial analytics processing, forecasting model evaluation, and compliance monitoring. The database serves as the storage component, maintaining user accounts, client profiles, financial records, periods, line items, compliance-related fields, and system configuration data. Additionally, the system incorporates a secure authentication mechanism to ensure that only authorized users can access sensitive financial and client information.  

The system process begins when the user logs into the platform using valid credentials. The user then inputs or updates client profiles and period-based financial records through the interface. These inputs are validated and stored in the database. The application server processes the stored data to generate financial summaries, present trend analysis, evaluate forecasting models, and produce frequency-aware forecasting results. Processed information, including financial trends, compliance status, client remarks, forecasting outputs, and report summaries, is displayed through the dashboard, analytics page, and reporting interface. This architecture ensures a centralized, secure, and organized approach to managing financial records and supporting data-driven bookkeeping review.

# Technologies, Concepts, and Theories

This section discusses the system model, process flow, forecasting concepts, and technologies used in the development of **SafeBooks: A Web-Based Financial Records and Compliance Monitoring System with Forecasting Analytics**. The system is designed to centralize client financial records, support compliance monitoring, generate financial analytics, and apply an evaluated forecasting model based on historical financial data.

---

## The System Model and Process Flow

SafeBooks follows a structured data processing model that begins with client profile management and financial record entry, then proceeds to compliance monitoring, analytics generation, forecasting model evaluation, and report presentation. This process ensures that the system does not only store bookkeeping data, but also transforms recorded financial information into useful summaries and forecasting outputs for bookkeeper review.

### Client Profile Management

The system allows authorized bookkeepers to create, update, retrieve, and manage client business profiles. These profiles include identifying information such as client name, business details, Taxpayer Identification Number (TIN), location, contact details, and related bookkeeping information. The TIN-based retrieval function supports faster and more accurate access to client records, especially when bookkeepers handle multiple clients with similar names or multiple business records.

### Financial Record Entry

Bookkeepers encode financial records into structured period-based entries. Each record may include sales, expenses, tax-related items, deadlines, notes, and multiple line items. The system validates required inputs before storing the records in the database to promote consistency and reduce incomplete entries. These stored financial records serve as the source data for summaries, compliance monitoring, analytics, and forecasting.

### Compliance and Client Activity Monitoring

The system monitors client activity, filing status, remarks, and upcoming compliance deadlines based on encoded records. Client remarks such as new, active, separated, and closed help describe the current bookkeeping status of each client. Filing status and deadline information support follow-up activities by helping bookkeepers identify clients that require attention.

### Financial Analytics Processing

The analytics component processes recorded financial data to generate summaries of sales, expenses, tax-related records, and net value. It also presents financial trends across selected periods to help bookkeepers review client financial movement. These outputs are descriptive in nature and provide the basis for understanding historical financial behavior before forecasting is applied.

### Forecasting Model Training and Evaluation

To support forecasting analytics, the study evaluates three forecasting models: Moving Average, Weighted Moving Average, and Linear Regression. Historical client financial records are used to train and test the models. Each model generates forecasted values, which are compared against actual values using Mean Absolute Error (MAE), Mean Absolute Percentage Error (MAPE), and Root Mean Square Error (RMSE). The model with the lowest forecasting error is selected as the final model for the system. In this study, Weighted Moving Average is selected because it achieved the best accuracy based on the evaluation results.

### Frequency-Aware Forecasting Integration

The selected Weighted Moving Average model is integrated into the analytics module using the original frequency of the financial records. Monthly records are forecasted monthly, quarterly records are forecasted only in their scheduled quarterly periods, and annual records are forecasted only in their annual schedule. This prevents different transaction schedules from being incorrectly combined into one forecast output.

### Dashboard and Report Presentation

The processed results are presented through dashboards and reports. The dashboard displays financial summaries, client activity, compliance status, and recent records, while the analytics and reports pages present trend summaries, forecasting results, and filtered report outputs. These views support bookkeeping review, follow-up, and decision-making.

## Forecasting Concepts and Theories

Forecasting is the process of estimating future values based on historical data. In SafeBooks, forecasting is applied to recorded financial data such as sales, expenses, and tax-related entries. The purpose of forecasting in the system is not to replace professional judgment, but to provide data-supported projections that help bookkeepers review possible future financial movement.

### Moving Average

Moving Average is a forecasting method that uses the average of previous values to estimate the next value. It is simple and easy to interpret, making it useful as a baseline forecasting model. However, because it treats previous values equally, it may respond slowly when recent financial movement changes significantly.

### Weighted Moving Average

Weighted Moving Average is a forecasting method that assigns different weights to previous values. In this study, more recent values are given greater importance because recent financial records may better represent current client financial movement. The system uses the Weighted Moving Average model for the final forecasting output after model evaluation shows that it produced the lowest forecasting error among the compared models.

### Linear Regression

Linear Regression is a forecasting method that estimates future values by identifying a linear trend in historical data. It is useful for detecting upward or downward movement over time. However, its performance depends on whether the historical financial data follows a reasonably linear pattern. For this reason, it is included as one of the comparison models rather than automatically used as the final forecasting method.

### Forecasting Accuracy Metrics

The forecasting models are evaluated using error metrics to determine which model produces the most accurate results.

**Mean Absolute Error (MAE)** measures the average absolute difference between actual and forecasted values. A lower MAE indicates smaller average forecasting error.

**Mean Absolute Percentage Error (MAPE)** measures the forecasting error as a percentage of the actual value. A lower MAPE indicates better forecasting accuracy in percentage form.

**Root Mean Square Error (RMSE)** measures the square root of the average squared differences between actual and forecasted values. RMSE gives greater penalty to larger forecasting errors.

Using these metrics allows the study to justify the selected forecasting model based on measurable performance rather than assumption.
